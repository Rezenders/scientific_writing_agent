# Plugin Setup

For existing paper repositories, the simpler and safer path is the conservative installer:

```bash
python3 /path/to/scientific_writing_agent/scripts/scientific_writing_agent.py install --repo-root .
python3 /path/to/scientific_writing_agent/scripts/scientific_writing_agent.py doctor --repo-root .
```

Use the plugin setup script below when you specifically want `.scientific-writing.json`-driven generated outputs.

## What the plugin manages

The repo-local plugin at `plugins/scientific-writing/` provides the `setup-paper-project` workflow.

It renders managed setup files from plugin templates using values in `.scientific-writing.json`.

Current managed outputs:

- `AGENTS.md`
- `CLAUDE.md`
- `.agents/HARNESS.md`
- `.agents/agents/*`
- `.agents/skills/**` (skill entrypoints and nested references)
- `.agents/context/*`

Adapter directories generated by the setup script:

- `.claude/agents` from `.agents/agents`
- `.claude/skills` from `.agents/skills`
- `.codex/agents` from `.agents/agents`
- `.codex/skills` from `.agents/skills`
- `.codex/context` from `.agents/context`

Plugin and marketplace metadata under `.claude-plugin/`, `.agents/plugins/`, and `plugins/scientific-writing/` is packaging metadata and should not be treated as workflow source.

## First run

Run from the repository root:

```bash
python3 plugins/scientific-writing/scripts/setup_paper_project.py --repo-root .
```

If `.scientific-writing.json` does not exist, it is created from the plugin template, then managed files are written.

## Rerun behavior

- If `.scientific-writing.json` exists, it is reused (not replaced).
- The script rewrites managed outputs from current config values.
- Manual edits to plugin-managed output files are overwritten on rerun.
- Exception: `.agents/context/style-preferences.md` is seeded once and thereafter
  project-owned; regeneration preserves it and refreshes its Codex context mirror.
- Harness adapter directories are regenerated as real files from `.agents/` for Overleaf compatibility.
- If `implementation.enabled` is `false`, generated outputs whose path contains `paper-implementation-checker` are skipped, and existing generated files at those paths are removed.

## Customization mode (plugin-first)

- In plugin-first mode, treat `.scientific-writing.json` as the main customization input.
- For structural or wording defaults across generated outputs, edit plugin templates in `plugins/scientific-writing/assets/templates/root/.agents/`.
- Avoid ad hoc edits directly in plugin-managed outputs unless you intentionally accept that rerun will overwrite them.
- If no implementation is available, keep `implementation.enabled=false` and skip implementation-only workflows in usage instead of deleting managed files.

When following `SETUP.md`, interpret steps that ask you to edit generated files as manual/non-plugin mode unless you accept overwrite on rerun; for durable plugin-mode updates, edit the corresponding `.agents` templates instead.

## Ownership boundaries

- User-owned: `.scientific-writing.json`, manuscript source files (for example `*.tex`, `*.bib`, figures), and `.agents/context/style-preferences.md`, plus files not listed above.
- Canonical workflow: `.agents/`, rendered from `plugins/scientific-writing/assets/templates/root/.agents/*.tmpl`.
- Adapters: `.claude/` and `.codex/` generated mirrors created by the setup script.

## Scientific grammar review

The `scientific-grammar-review` skill and `references/grammatical-patterns.md` are
packaged under `assets/templates/root/.agents/skills/scientific-grammar-review/`.
The recursive template renderer installs both; adapter generation copies nested
resources too. Keep these templates synchronized with canonical `.agents/` edits.
The preference template is installed only if the project-owned file is missing.
No extra agent, mandatory review pass, or configuration parser is required.
